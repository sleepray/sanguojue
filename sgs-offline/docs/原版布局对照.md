### 4.2 排布算法（`LayoutEquipCards`，逐行抄录）

```js
LayoutEquipCards(t = false, e = 0, i = 0) {
  const a = e, n = i + 55, r = 30;          // 默认 n = 55, r = 30
  for (const s of this.equipCardUIs) {
    s.EndX = a;                              // 默认 x = 0
    switch (s.Card.FirstSkill.CardZoneType) {
      case TREASURE:              s.EndY = n - 90; break;   // -35
      case WEAPON:                s.EndY = n;      break;   // +55
      case ARMOR: case WEAPON_EX: s.EndY = n - r;  break;   // +25
      case HORSE_DEF:             s.EndY = n - 60; break;   // -5
      case HORSE_ATT:
        if (!hasDefHorse && hasHorseDefZone)      s.EndY = n - 60;
        else if (!hasTreasure && hasTreasureZone) s.EndY = n - 90;
        else { s.EndY = n - 60; s.EndX = a + 74; }          // 双马：右移 74
        break;
      case ZONE_SKILL:            s.EndY = n;      break;
    }
    s.y = s.StartY = s.EndY;
    // 首次出现直接落位；后续用 MoveLocalTo(..., 0.3s) 补间
  }
}
```

换算到座位坐标（座位中心原点，y 上；容器 `equip` 原点在座位 (-62, -62.7)）：

| 槽位 | 本地 (x,y) | 座位内左下角 (x,y) | 占位 |
|---|---|---|---|
| 武器 | (0, 55) | (-62, -22.7) | 142×30 |
| 防具 | (0, 25) | (-62, -52.7) | 142×30 |
| -1 马（防） | (0, -5) | (-62, -82.7) | 142×30 |
| 宝物 | (0, -35) | (-62, -112.7) | 142×30 |
| +1 马（双马并存） | (74, -5) | (12, -82.7) | 142×30 |

四件竖排合计 **142 × 120**，底边正好落到座位下沿 (-116) 之上 3.3px —— 原版是**算好的贴边**。

### 4.3 与当前实现对照

| 项 | 原版 | 当前 | 建议 |
|---|---|---|---|
| 单件尺寸 | 142×30 横条 | 26×26 方块 | 改成横条，高度 ≥ 原版一半 |
| 布局 | 单列竖排 y 55/25/-5/-35 | 2 列网格 gap 3 | 改单列，`bottom` 对齐座位底 |
| 信息 | 图标 + 花色 + 点数 + **名称** | 仅图标 | 至少补名称（8–10px 楷体） |
| 总量 | 142×120 | 55×55 | 面积差 5.6 倍 |

> 27/29px 这类小方块在高分屏上会把装备名完全丢失，这是"4 件就溢出/错位"的根因：**不是格子不够大，而是表达方式不同**。2×2 网格只是把溢出藏起来了。

|---|---|---|
| 基准尺寸 | `M_CARD_SIZE = 126×174` | `--hand-w: 112px / --hand-h: 156px` |

| 容器 | `TYt.WIDTH=350, HEIGHT=123` | `.hand { position:absolute; inset:0 }` 全屏铺开 |

| 选中位移 | `NORMAL_Y=-8` → `SELECTED_Y=+7`（**上抬 15px**） | `translateY(calc(var(--y) - 26px))`（上抬 26px） |

**差异**：当前手牌比原版大 36%，且缺少"按容器宽度动态压缩 gap、允许最多 2px 重叠"的算法——牌一多就会横向溢出，这解释了截图里手牌堆挤到边的情况。

**建议**（优先级低于装备）：
1. 桌面版手牌改 82×113 或等比 0.65；
2. 引入 `gap = clamp((容器宽 - 82·n)/(n-1), -82, 2)` 的重叠算法；
3. 选中上抬收到 15px。

| `.seat-hp` | left 38 / bottom 8 | left 1.1 / top 208 | 偏右 37 | `left:1px; bottom:24px` |

### 10.2 唯一阻塞项：`.seat { overflow: hidden }`

`css/style.css:370` 的 `.seat` 同时有 `border-radius: 9px; overflow: hidden`。
国别竖条（-2.7 / -2.1 / 236.6 高）、牌数角标（-9.1 / 206）、状态图标（182）**都超出座位盒**，
只要 `overflow:hidden` 还在，这三块一定会被裁掉——这是三段式做不出来的**根本原因**。

最小补丁（不动 HTML）：

```css
/* 放开座位裁剪，把圆角裁切下放到立绘层 */
.seat { overflow: visible; }
.seat-art { overflow: hidden; border-radius: 8px; }
```

> `.seat-veil` 已 `inset:0` 且是渐变，不裁也不会溢出；`.seat-art img` 用 `object-fit:cover` 仍靠 `.seat-art` 收圆角。

## 11. 手牌 112×156 vs 82×113：两套方案

### 11.1 先把数字摆清楚

| 基准 | 尺寸 | 出处 |
|---|---|---|
| 原版卡牌基准 | 126 × 174 | `aF.M_CARD_SIZE` |
| 原版紧凑手牌 | **81.9 × 113.1** | 基准 × `cardScale 0.65`（容器 `TYt`） |
| 原版选牌窗口 | 103 × 143 | 基准 × `s = 0.82`（`HanJunSelectCard` 排布） |
| 当前单机版 | **112 × 156** | `--hand-w/--hand-h`（>1440 基准，本次 1600 截图实测 ≈112×156） |

当前值 = 基准 × **0.889**，比原版紧凑手牌大 **36.7%**，比选牌窗口大 8.7%。

### 11.2 方案 A：保留可读性（**推荐**）

直接采用原版**自己的** 0.82 档 —— 不是拍脑袋的数字，是原版在"需要看清牌面"的窗口里的取值。

```css
:root { --hand-w: 103px; --hand-h: 143px; }
.hand-card { bottom: 20px; }
```

- 卡面文字/花色仍清晰（112→103 只缩 8%，视觉几乎无感）；
- 容器 ~1100px 时，**不重叠可放 10 张**（103×10 + 2×9 = 1048），比现在多 1 张；
- 与 `.hc-suit / .hc-rank` 现有字号兼容，不需要重排字。

### 11.3 方案 B：严格原版

```css
:root { --hand-w: 82px; --hand-h: 113px; }
.hand-card { bottom: 20px; }
```

- 完全对齐 `cardScale 0.65`；
- 不重叠可放 **13 张**（82×13 + 2×12 = 1090），长手牌局不会压叠；
- 代价：82px 宽下 `hc-name`（卡名竖排）会挤，需要把 `.hc-name` 字号降到 9px 或只留角标。

### 11.4 两套方案共有的两个问题（与尺寸无关）

1. **上抬距离**：原版 `NORMAL_Y = -8` → `SELECTED_Y = +7`，即选中**上抬 15px**；当前是 `translateY(-26px)`，多抬 11px，牌多时容易顶到操作条。建议 `-26px → -15px`。
2. **扇形**：原版紧凑手牌容器 `TYt` 是**平铺不旋转**（`s.pos(x, NORMAL_Y)`，无 rotation）；当前 `layoutHand()` 有 `rot = off × 2.1°`（±8°）+ `y = |off| × 2.4`（最多 17px 弧）。
   - 这是**当前实现的加法**，不是原版行为；但它对可读性有利，建议保留，只在方案 B（82px）下把 `rot` 系数从 2.1 降到 1.4，避免小卡旋转后互相压边。

### 11.5 选型建议

| 场景 | 选 |
|---|---|
| 优先"像原版" | B（82×113） |
| 优先"看得清 + 少改动" | **A（103×143）** |
| 想两者兼得 | A，并在设置里留一个"紧凑手牌"开关切 B |

`layoutHand()` 的 gap 算法（`clamp((avail - cw*n)/(n-1), -cw, +2)`）已经与原版一致，**只要改 `--hand-w/--hand-h` 就会自动生效**，不需要动 JS。
