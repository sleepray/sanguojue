### 1.3 判定口径

- **以代码实际执行为准**：不因“文件里出现过技能名/有 case 分支”判为完整；黄天/制霸/巧变就是“有分支但无入口”的反例。
- 状态定义：
  - **完整**：正常路径与文案一致，未发现影响结算的缺口。
  - **简化**：主路径可用，但缺少分支、限制、目标/费用校验或交互选择。
  - **行为不符**：实际结算与文案相反/明显错误，或实际不可达。
  - **未实现**：没有任何实现引用。

## 4. 严重错误

### 4.1 崩溃：火攻 + 无懈（T66）

- **现象**：目标只有 1 张手牌（【无懈】）时，对其使用【火攻】；目标用【无懈】抵消，另一名角色再【无懈】反抵消，火攻继续结算时崩溃：
  `TypeError: Cannot read properties of undefined (reading 'suit')`
- **根因**（`js/cards.js:665-671`）：
  ```js
  if (!target || !target.hand.length) return;
  if (await this.isNullified(vc, target, p)) return;   // 这里可能把目标手牌打空
  const shown = target.hand[this.rand(target.hand.length)]; // 长度为 0 → undefined
  ...
  const pool = p.hand.filter((c) => c.suit === shown.suit); // 崩溃
  ```
  手牌检查在无懈询问**之前**；无懈链结算后没有复查。
- **复现**：`T66`（确定性用例）；`node tools/audit_sim.js 6 6` 的 8p seed 7001 也复现了同一路径。
- **修复方向**：无懈返回后重新判断 `target.hand.length`；或对 `shown` 判空后直接返回。

### 4.2 回归：黄天、制霸、巧变“有分支但不可达”

`buildSkillActions`（`js/skills.js:77-149`）是出牌阶段动作的唯一来源。冻结快照里它已不再生成以下三个技能的入口，但 `useSkillAction` 仍保留 case，形成“代码在、玩家永远点不到”的假实现：

| 技能 | useSkillAction 分支 | 问题 |
|---|---|---|
| 黄天 | `js/skills.js:379-386` | 无 build 入口；群势力角色无法把【闪】/【闪电】交给张角 |
| 制霸 | `js/skills.js:361-368` | 无 build 入口；且语义仍是“孙策主动拼点”，官方应由其他吴势力角色发起 |
| 巧变 | `js/skills.js:388-414` | 无 build 入口；即使直接调用，“移动场上一张牌”实现为 `toDiscard`（弃置），不是移动到另一角色区域 |

- **为什么上一轮没发现**：`T26/T27/T33` 只断言“孙策不应有动作 / 动作能执行”，没有断言“应该有入口”，因此假通过。本轮已把“可触发”单独列为检查项。
- **修复方向**：恢复三者的 build 入口；制霸改为“吴势力角色发起”的触发式技能；巧变移动牌写入目标区域（装备/判定区）。
