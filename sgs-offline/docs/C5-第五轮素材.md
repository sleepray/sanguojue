### 1.3 修复

1. **公开身份判定集中化**（`js/ai.js:83` `knownRole()`）：
   - 只在“自己 / 1v1 / 团队 / 斗地主 / 主公 / 已 revealed”时读 `role`；
   - 其余返回 `null`，交给行为推断。
   - `isLord(q)` 只看 `q.seat === game.lordSeat`（主公座次公开），不再读 `q.role`。
2. **关系/人数统计**（`js/ai.js:91` `revelationCounts()`）：先 `q.revealed` 再读 `q.role`，只统计已公开身份；内奸均势不按真实人数透视。
3. **替换所有其他玩家 `.role` 读取**：`threatOf`、`scoreTarget`、目标价值、AOE、内奸救桃等改为“主公座次/已知身份”。
4. **`jixi` 总牌数**：新增 `publicCardCount(q)`（`js/ai.js:256`），用公开的 `hand.length + equips + judges` 计算，不再调用 `allCardsOf(他人)`。
5. **引擎无懈询问时序**（`js/cards.js:512`）：`isNullified` 不再 `if (!canPlayWuxie(q)) continue`，所有存活 AI 都走同一 `askWuxie` 询问；`askWuxie` 对 AI 即使 `options=[]` 也发请求（`js/cards.js:538`），人类只在有可选项时弹窗。这样不会出现“没有无懈的人被跳过/没有思考停顿”的可推断差异。
6. **公开事件补目标**：无懈的 `recent.use` 事件补 `targets`（`js/cards.js:526`），供推断使用，不泄露隐藏手牌。

## 2. 1c-2 公开行为推断

### 2.1 设计

- 每个 AI 私有：`ai.infer = { scores: {seat: -6..6}, tail }`，**不写回玩家数据、不进存档**。
- 每次 `decide()` 前 `scanPublicEvents()`（`js/ai.js:137`）增量读取 `game.recent` 公开事件：
  - `use` 事件：`sha/huosha/leisha/juedou/guohe/shunshou/huogong/jiedao/nanman/wanjian/lebu/bingliang/shandian` 视为敌意；`tao/wuzhong/taoyuan/wugu/wuxie` 视为援助。
  - `rescue(phase=save)`：救起濒死者的行为。
- 评分（`observePublicEvent`，`js/ai.js:149`）：
  - 对主公敌意：按自己的阵营放大 ±2.5（忠臣记 -，反贼记 +，内奸在反贼仍在时记 -）；
  - 对自己敌意 -3 / 援助 +3；
  - 对已知阵营的友/敌：攻击敌方 +1.2、攻击友方 -1.2，援助反向；
  - 救主公/救自己 +3，救已知友方 +1.5，救敌方 -。
- 阈值：普通/忠/反 ±2，内奸 ±3（`inferred()`，`js/ai.js:123`）；持续行为会累加/抵消，超过阈值才把 neutral 改判 friend/enemy。
- `relation()`（`js/ai.js:184`）：公开身份优先；无公开身份时返回 `inferred(seat)`；1v1/团队/斗地主仍按公开阵营。
- 内奸：仍用“反贼在则保主公、反贼清空后与主公为敌、按已公开人数均势”的阵营目标，并叠加行为推断。
- `recent` 窗口滚动导致旧事件丢失时清空分数重扫（`scanPublicEvents`），避免重复累计。

## 4. 引擎替 AI 决策的分支检查

1. **无懈询问（已修）**：原 `cards.js:534` 用 `canPlayWuxie` 过滤，只有手上有无懈/看破黑牌的人才被询问；现在所有存活 AI 都询问，空 options 也发请求（`cards.js:512/538`），T266 锁定“三人均无无懈仍各问一次”。
2. **问桃**（`cards.js:1156`）：无牌者不弹空窗（人类体验），但 `game.js` 的 `recent.rescue` 对每个存活座位都先记 `ask` 再记 `save/pass`，没有“谁被跳过”的结构化差异；AI 也不读取他人请求，不构成 AI 可见泄露。
3. **鬼才/鬼道**（`game.js:1009`）：用 `hand.length` 决定是否询问；手牌数量本身公开，不泄露具体牌。
4. **天香/看破等技能条件**：检查的是目标自己的手牌（本人可知），引擎不把内容写给其他 AI；Proxy 审计中无 hand/deck 读取违规。
5. **请求扫描**：`scanRequest` 对 `req.cards/options` 的他人手牌 id 和 `deck/judge/pindian/...` 字段检查，250 局 0 条。

## 6. 遗留/说明

1. 推断只使用 `game.recent`（公开事件），不使用日志文本；`recent` 最多 200 条，滚动丢失时清分重扫，极端长局可能出现推断“失忆”，不影响不变量。
2. 无懈“对全体 AI 询问”会让 AI 在没有无懈时也进入一次 `decide`（空 options 立即返回），属于有意为之的等价延迟；人类仍只在有牌时弹窗。
3. Proxy 审计统计的是“AI 读取路径”；引擎内部方法（如 `distance`）读取真实对象不经过 Proxy，但 AI 拿不到其内部字段；`allCardsOf(他人)` 这类返回他人手牌的调用点已改为公开数量计算。
4. 任务 2（身份标记持久化）等 B 的 UI 冻结后再做；本文件未改 UI/存档。
