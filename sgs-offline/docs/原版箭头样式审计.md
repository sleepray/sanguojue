# 原版「方向线 / DirectionLine」样式审计

审计对象：`sgs_offline`（原版《三国杀OL》解包，只读）中的 `TableUI/DirectionLine` 预制体
对照对象：`sgs-offline`（当前单机版）的 `flashArrows()` / `drawAim()` 自绘 SVG 箭头
结论日期：2026-11-13　｜　本轮只读原版与当前工程，未改动任何游戏代码

---

## 0. 一句话结论

原版方向线**不是一条线**，而是**两层叠加的暖橙金「光带」**：

1. **基础层**：一张 136×33 的贴图 `seatui_directline`，被拉成「出牌者→目标」的**直条矩形**（运行时高 28px），
   自左向右**生长 0.4s**，结束时按 `fillAmount 1→0` **收缩 0.4s** 消失。颜色是**橙金 #E47816 + 白热芯 #F4FFDE**，
   上下柔化渐隐，**实心、无虚线、无箭头**。
2. **高品质层**：仅当出牌者武将 `Gradation ≥ 4` 时，额外叠一段 Spine 动画 `zhixiangxianlong`（**金龙拖尾**，
   8 帧 / 15fps / 0.567s 循环），龙头朝向目标——**龙头就是"箭头"**，原版没有任何三角 marker。

当前实现用**蓝色 #80CEFF、2.2px、虚线 7/6、贝塞尔弯曲、末端三角箭头**，与原版在
**颜色、线型、粗细、形状、动画、语义**六个维度全不一致。

## 2. 原版样式：颜色 / 线型 / 粗细 / 动画

### 2.1 颜色（贴图实测，非推测）

逐像素采样 `seatui_directline`（x=68 竖直剖面，y=0 顶 → y=32 底）：

| 位置 | hex | RGB | alpha | 角色 |
|---|---|---|---|---|
| y=16（正中） | `#F4FFDE` | 244,255,222 | 255 | **白热芯**（峰值 80 处达 `#FFFFEE`） |
| y=15 / 17 | `#F2F2C3` / `#F1EEBC` | 242,242,195 | 245 | 淡黄过渡 |
| y=13-14 | `#E4D968` / `#E4BD26` | 228,189,38 | 216-244 | **金** |
| y=12 / 19-20 | `#E4A203` / `#DE9100` | 228,162,3 | 189-198 | 琥珀 |
| y=21-27 | `#E37610` ~ `#E67C1C` | ≈228,120,22 | 70-162 | **橙金主体** |
| y=9-11 | `#E46B15` / `#E4840B` | — | 134-159 | 主体外沿 |
| y=0-3 / 29-32 | `#BD5E0F` ~ `#CC6611` | ≈190,94,15 | 14-41 | 暗橙柔边 |

水平方向：x=8~128 区间 alpha 稳定在 **200~255**，只有最两端 6px 快速衰减到 1 ——
即**光带主体是实心均匀的，只在两端软化**，没有任何虚线断口。

**归纳出的 3 个可用色值：**
- 主体橙金 **`#E47816`**（228,120,22）
- 亮金 / 次高光 **`#E4BD26`**（228,189,38）
- 白热芯 **`#F4FFDE`**（244,255,222）～`#FFFFEE`
- 暗橙柔边 **`#C05F0F`**（192,95,15，低 alpha 14~40）

> 注意：原版这个颜色**不是** UI 装饰金（`#D8B36A` / `#E9C26A` 那种哑光金），
> 而是**火焰/熔金/朝阳**的高饱和暖橙，且**中心过曝到接近纯白**。这是当前实现最容易做错的地方。

### 2.2 线型与粗细

| 维度 | 原版 |
|---|---|
| 形状 | **直线**（`rectTrans.right = dir.normalized`，矩形只做旋转，不做弯曲） |
| 截面 | 矩形**竖直方向做柔化渐变**（中心 255 → 边缘 14），不是硬边描边线 |
| 粗细 | 贴图 33px 高，运行时 `height = 28`（代码里 `this.height=28`）→ 竖向下压 28/33 ≈ 0.85 |
| 虚线 | **无**（`Image.Type.Filled` 只有 fillAmount，没有 dash） |
| 箭头 | **无三角 marker**。参考值造型来自高品质层的龙头 |
| 端点 | 两端各约 6px 软衰减，不是平头 |

### 2.3 动画时序（JS 层实测）

```
setLine():
  size.y = 28;  size.x = 0;  rectTrans.sizeDelta = (0,28)
  dir = endPos - startPos;  size.x = |dir|
  rectTrans.right = dir.normalized          // 只旋转
  spineObj.SetActive(gradation>=4)          // 金龙层开关
  if (spine) Skeleton.ScaleY = (angle 在 90~270) ? -1 : 1   // 保持龙头朝向可读

startLineTween():
  展开: rectTrans.DOSizeDelta(size, 0.4)    // 宽 0 → 距离，0.4s
  收起: imgFilled.DOFillAmount(0, 0.4)      // fill 1 → 0，0.4s（Filled/Right）
```

层级：`localPosition.z = US.LayerGroupZDepth.pop - 100` —— **压在座位之下**。

### 2.4 触发语义（原版）

```js
class aKt {                                    // 方向线容器
  ShowLine(fromSeatUi, targetSeatUis) {
    targets.forEach(e => {
      let useSpine = false;
      if (fromSeat.Seat.Gradation >= hit.MinLineEffectGradation) useSpine = true;  // 4
      line.Init(fromSeatUi, e, useSpine);
    });
  }
  ShowByQueue(...)                             // 多目标排队播放
}
```

- 入口：`RW.SHOW_DIRECTION_LINE_EVENT` → `showDirectionLine(seat, targets, isQueue)`
- 阈值：`hit.MinLineEffectGradation = 4`（即**出牌者**武将品质 ≥ 4 才有金龙）
- "金色指向线" 是设置项文案：`NeedShowViewEffectBtnList = ["技能特效","金色卡牌特效","金色指向线","闪卡特效"]`
  → 金龙层在运营层面被当作**付费/高品质特效**

### 2.5 是否为「龙形 / 光带」

**两者都是，分两层。**

`out/orig_direction_spine_frames.png` 显示 8 帧全部是**金色龙头 + 向右拖曳的火焰能量尾迹 + 星点粒子**：
龙头在左（贴图朝向），运行时 `initialFlipX=1` 水平镜像 → **龙头朝右（朝目标）**。
它不是一条线，而是一颗"龙头流星"。

## 3. 原版是否给 DirectionLine 赋过颜色？

**没有。** 逐项排查结论：

| 检查项 | 结果 |
|---|---|
| prefab `Image.m_Color` | `(1,1,1,1)` 纯白，静态 |
| prefab `SkeletonGraphic.m_Color` | `(1,1,1,1)` 纯白，静态 |
| JS `nKt` 类（方向线本体） | 只在构造时取 `GetImage()` / `GetSkeletonGraphic()`，**全文无 `color` / `SetColor` / `tint` 赋值** |
| JS `aKt` 类（容器） | 仅做队列/生命周期，**无颜色相关调用** |
| 唯一的动态变换 | `this.spine.Skeleton.ScaleY = (z>90&&z<270)?-1:1` —— **只翻转，不改色** |
| `Assembly-CSharp.decompiled.cs` | grep `DirectionLine` = **0 命中**（该类由 Puerts JS 驱动，不在 C# 侧） |
| `zfjLineImg`（TableUI 中的另一个线引用） | 仅在两处赋值 / 置空，**从未被使用**，与本效果无关 |

→ **原版方向线的颜色 100% 来自贴图本身**，没有任何运行时染色。
这也解释了为什么材质 `_OutlineColor` 虽然是黄色却看不出黄边——它压根没被当作视觉主色使用。

## 5. 最小改法建议

> 以下只是建议，本轮未改动任何代码。三个方案按改动量递增，可按阶段落地。

### 方案 A：只改 CSS（0 行 JS，立刻去掉"蓝色虚线"观感）

```css
/* css/style.css:1423 替换 */
.aim-layer path.is-transient {
  stroke: rgba(228, 120, 22, .72);        /* #E47816 主体橙金 */
  stroke-width: 9;                         /* 光带量级，替代 2.2px 细线 */
  stroke-linecap: round;
  stroke-dasharray: none;                  /* 原版无虚线，必须去掉 */
  stroke-linejoin: round;
  filter:
    drop-shadow(0 0 5px rgba(232, 140, 40, .75))
    drop-shadow(0 0 13px rgba(255, 170, 60, .40));
}
```

效果：从「冷蓝细虚线」变成「暖橙宽光带」，语义与色温立刻对齐；
仍缺白热芯，且弯曲未修。

### 方案 B：CSS + 少量 JS，三层描边复刻光带剖面（推荐，改动可控）

把瞬时箭头渲染从 1 条 path 改为 3 条同心 path（同一 `d`，不同 class），
等价于原版贴图「外橙→中金→内白」的竖向剖面：

```css
/* 外层柔光：宽度最大、最透明，负责"发光" */
.aim-layer path.is-transient-glow {
  stroke: rgba(192, 95, 15, .38);   /* #C05F0F */
  stroke-width: 16; stroke-linecap: round; stroke-dasharray: none;
  filter: blur(3px);
}
/* 主体：橙金 */
.aim-layer path.is-transient {
  stroke: rgba(228, 120, 22, .90);  /* #E47816 */
  stroke-width: 9; stroke-linecap: round; stroke-dasharray: none;
}
/* 白热芯：最细、最亮 */
.aim-layer path.is-transient-core {
  stroke: rgba(250, 255, 224, .95); /* #FAFFE0 ≈ #F4FFDE */
  stroke-width: 2.6; stroke-linecap: round; stroke-dasharray: none;
}
/* 16:40 新增的粒子点，必须补规则，否则按 SVG 默认填成黑色 */
.aim-layer circle.aim-spark {
  fill: rgba(255, 242, 196, .92);
  stroke: none;
}
```

配套三点（沿用 16:40 那次改动里已经做对的部分）：
1. `aimPath()` 的 `bendScale` 传 `0`（原版是直线，`rectTrans.right = dir`）。
2. 去掉 `marker-end`（原版无三角箭头）；若担心看不清目标，改为目标座位描一圈暖金。
3. 若保留展开动画：用 `stroke-dasharray: L L; stroke-dashoffset: L→0`，**0.4s**（与原版 `DOSizeDelta(0.4)` 同频）。

宽度换算（原版 28px 是在 1920 基准）：
`光带高度 ≈ 画布宽 × 28 / 1920 ≈ 1.46% 画布宽`。
1600px 宽 → ≈ 23px；1090px 宽（当前移动端截图）→ ≈ 16px。
建议主体 `stroke-width` 取该值的 **0.6 倍**，辉光取 **1.7 倍**，白芯取 **0.28 倍**。

### 方案 C：直接用原版贴图（最忠实）

用本轮导出的 `out/orig_direction_texture.png`（136×33）替代描边：

```html
<defs>
  <pattern id="dlBand" patternUnits="objectBoundingBox" width="1" height="1">
    <image href="assets/ui/seatui_directline.png" width="136" height="33"
           preserveAspectRatio="none"/>
  </pattern>
</defs>
<!-- 用一条直线 path，stroke 换成贴图 pattern -->
<path d="M x1 y1 L x2 y2" stroke="url(#dlBand)" stroke-width="16" fill="none"/>
```

这跟 Unity 的 `Image.Type.Filled` + `sizeDelta` 拉伸**行为等价**（横向拉伸、纵向压缩到目标高度），
是唯一能同时还原「白热芯 + 橙金 + 柔边」的方案。代价：需要把 PNG 放进 `assets/`，
并放弃 `stroke-dasharray` 的生长动画（改用 `clip-path` 或逐帧 `width`）。

### 方案 D（可选，工作量最大）：补金龙层

把 `out/orig_direction_spine_frames.png` 拆成 8 张 PNG，做一个 15fps 的
`<img>`/`background-position` 逐帧动画，挂在目标端内侧 ≈122px 处（对应 prefab `anchoredPosition.x = -121.8`），
水平镜像（`initialFlipX=1`），并在出牌者品质 < 4 时**不显示**。

## 6. 未确认项 / 风险

1. **Spine 实际渲染像素尺寸未验证**：`SkeletonDataAsset.scale = 0.01` 而 `spine` 子节点
   `sizeDelta = (0,12)`，两者与「28px 高光带」的配比无法在静态资源上自洽。
   `SkeletonGraphic` 会在运行时按 skeleton bounds 匹配 RectTransform，本轮**没有运行原版**，
   因此只报告 `256×128`、`scale 0.01`、锚点 `-121.8`，不把最终 px 写成结论。
2. **黄描边未启用**：材质里有 `_OutlineColor=(1,1,0,1)`、`_OutlineWidth=2.57/3`，
   但 keywords 中没有 `_OUTLINE_ON`，判定为不生效；这是**静态推断，非运行证据**。
3. **横向拉伸失真**：`Image.Type.Filled` + `Simple` 会把 136×33 贴图**非等比**拉长到任意距离，
   原版长线必然有横向拉伸/接缝。方案 C 若用 `preserveAspectRatio="none"` 会复刻同样的失真；
   若要更平滑，应改成 9-slice（但原版 border=0，**原版没有做九宫格**）。
4. **原版「选择目标」的视觉**不在本结论内：`SHOW_TARGET_EVENT` / `zfjLineImg` 线索显示另有实现，
   但 `zfjLineImg` 在全量 JS 中只被赋值、从未被使用，需另行审计。
