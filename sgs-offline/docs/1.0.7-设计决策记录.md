# 1.0.7 设计决策记录

> 来源：2026-11-16 至 11-17 与 Claude（Cowork）讨论第一到第四轮提示词时定下的决策。
> 用途：后续会话（Claude Code 或其他模型）接手时先读本文件，**不要推翻已定方案**；如需改动，先和用户确认。

## 1. 工作流程
- 用目标模式提示词驱动模型执行，主控 + 子 agent：A 布局检测、B 交互设计、C 卡牌/技能/存档
- 每轮先跑基线，修完跑回归，出报告；报告由人工复核截图后再出下一轮提示词
- 经验教训：
  - 检测工具会漏报（字号按 transform 前计算、图标被当成非文字跳过），「0 个问题」不能全信，必须人工看截图
  - 模型截图常截到动画中间态，必须用 waitForIdle()，并用「动画关闭」再测一次
  - 测试数据必须用真实牌名、真实武将，不用「装备2」这类假数据
  - 扩大点击热区只能用透明伪元素（无背景/阴影/滤镜）；不能放大带背景或 backdrop-filter 的元素本身，座位内角标禁止 backdrop-filter/filter
  - 所有显示卡名/装备名都走卡名归一化函数，页面不得出现拼音卡名；layout_check 需有纯拼音文本检查
  - 示意图迭代多版后容易互相冲突：只保留一张参照图（牌桌 docs/手机横屏布局示意v6.png；主菜单与牌桌比例 docs/主菜单与比例示意v7.png，冲突时以 v7 为准），旧图移到 docs/示意图_已作废/

## 2. 平台与视口
- APK 锁定横屏（sensorLandscape），不做竖屏 APK；竖屏只对网页/PWA 有意义
- 视口单位是 CSS 像素；检测视口：792×323（折叠屏外屏横屏，最矮）、915×412、997×448（与模拟器一致）、720×619（折叠屏内屏）、1280×800、1376×1032、412×915（仅网页兼容）
- 修复循环中增量运行，全量只在开始和结束各跑一次；截图 JPEG q70、DPR 1；out/ 超过 500MB 停止

## 3. 手机横屏整体布局（高度 ≤520px）
- 顶栏 ≤40px：左「牌堆 / 弃牌 / 回合」+ 自动存档后短暂显示「已自动保存」；中间平时显示阶段，需要表态时显示具体提示（如「太史慈 濒死，是否使用【桃】？」）；右「暂停 / 战报 / 更多」
- 「更多」菜单：设置、托管、保存 │ 投降、退出（危险项在分隔线下，二次确认）
- 底部玩家区按内容定高，不超过视口高度 35%；牌桌 ≥50%
- 第三轮已定位的根因：style.css 中 `min-width:761 & max-height:820` 固定底栏 290px 的规则命中了所有手机横屏；手机横屏样式要合并成一个区块，不要再叠加 @media
- 设计参照：平板 1280×800 布局（左头像、中手牌、右技能/装备卡图）结构好，手机横屏按同一思路缩小，平板布局不改

## 4. 其他玩家座位
- 武将牌：左上势力，右上身份牌，右下手牌数（与体力同一行），上沿正中判定图标
- 体力：上限 ≤5 用圆点；>5 或放不下时用「♥ 当前/上限」（董卓主公 9、地主 10）
- 身份牌：未知「?」；主公金色「主公」；自己标记的显示彩色单字（忠 / 反 / 内 / 主），和公开身份样式可区分；阵亡显示真实身份全称、武将牌变灰；点击弹出标记菜单（主公 / 忠臣 / 反贼 / 内奸 / 清空），仅自己可见，热区 ≥32px；选目标时点击座位是选目标，不弹菜单
- 判定：武将牌上沿正中红色单字（乐 / 兵 / 电），最多 3 个，≥14px（判定牌只有 3 种，单字足够）
- 装备「外挂栏」：
  - 单列，挂在武将牌侧面，不遮脸和名字
  - 方向朝牌桌中心：左半边座位挂右侧，右半边座位挂左侧，左右镜像；正上方中间的座位挂右侧；左右按座位中心点相对牌桌中线判断，不按座位编号写死
  - 每行「类型色块 + 牌名」≥12px，最多 4 行，高度不超过武将牌
  - 放不下时自动降级：完整牌名 → 两字简称 → 仅类型色块，只降级放不下的那一列；最紧处通常是角落座位与相邻顶排座位之间
  - 没有装备不显示；外挂栏算座位的一部分参与重叠检测
- 装备提示条不再在座位旁弹出，改为外挂栏对应行闪一下 + 写入战报
- 被否决的方案：装备挂在武将牌下方（顶排放不下时会伸进出牌区）、装备/判定分挂两侧（相邻座位装满时互相抢位置）、所有座位统一挂右侧（右侧两座位冲突）、判定并入外挂栏（占第二列，放不下）

## 5. 自己的玩家区
- 从左到右：头像 | 装备列 | 手牌区 | 技能列
- 头像：左上自己的身份，右上红色判定单字（点击看全名），下方体力
- 装备列：放左侧（和头像同属「我的状态」，右侧留给操作）；固定 4 格「武器 / 防具 / +1 马 / −1 马」，每格约 90×24px；有牌显示「类型 + 两字简称 + 花色点数」，装备格不显示攻击范围（单独数字易误读），点击或长按的说明浮层和武将详情里显示「攻击范围 N」；空槽完全不显示但位置保留；列宽始终保留；点击看说明；可主动发动的装备（丈八蛇矛）可发动时高亮、点击即发动
- 技能列：竖排小行（约 92×30px），主动技能金色点击即发动，被动 / 锁定 / 主公技灰色、在可发动时机高亮；行高 30px 低于 44px 是为放下 3 行的取舍，用宽度补偿；超过 3 个显示「更多技能」；被动技能触发时闪一下
- 技能说明必须可查：点主动技能进入发动流程时显示说明浮层直到确认/取消；点被动技能弹出说明浮层，点外部关闭；ⓘ 或长按只看说明
- 武将详情（长按任意头像）是兜底入口：全部技能及说明、身份（按可见性）、体力、手牌数、完整装备列表（含花色点数和效果）、完整判定列表；任何布局调整都不能削减
- 手牌：少时居中不重叠；15 张时允许重叠但每张露出 ≥36px，选中抬起，放不下可横向滑动
- 卡面：牌名和点数分区，不互相遮挡
- 花色：所有显示花色点数的地方都取牌的实际花色点数；♥ ♦ 红色，♠ ♣ 深色（深色背景上用浅灰白）

## 6. 动作按钮与读秒
- 不使用带背景框的悬浮动作栏，牌桌中间完全留给打出的牌（去掉中央「出牌阶段」圆圈）
- 按钮放在牌桌右下角空处：右列座位及其外挂栏左侧、手牌区正上方，右对齐，无背景框
- 按钮随状态切换：结束出牌 / 确认·取消 / 打出·不响应 / 弃牌；高 40–44px，宽度自适应
- 读秒放进主按钮（「结束出牌 36s」）+ 手牌区上沿 3px 进度条
- 原手牌上方的状态行取消，提示文字移到顶栏中间

## 7. 存档
- 不做「保存任意时刻」：引擎是 async/await 状态机，结算中途无法序列化
- 1 个自动存档（每个回合开始都写，含 AI 回合）+ 3 个手动槽位（保存本回合开始时的进度，文案写明）
- 主菜单「继续游戏」读自动存档并显示「模式 · 第 N 回合 · 时间」；新增「读取存档」列出全部槽位，可读取、删除
- 每个槽位单独 localStorage 键；旧 sgs.save.v1 迁移为自动存档；写入失败要提示；快照里保存随机数状态
- 自动演示不读写任何存档；新游戏只覆盖自动存档；对局结束只清自动存档
- 第四轮待验证的疑似缺陷：演示清存档、退出判负后存档未清、保存失败仍提示成功、读档后回合数累加

## 8. 规则口径（第二轮裁定）
- 手牌或装备区的牌因任何原因离开，都走 afterLoseCards
- 判定区的牌离开不触发连营、枭姬
- 置入装备区不算「获得牌」（直谏、界结姻不触发清俭）
- 识度、筹伐、宴戏、三陈的 AI 策略只用公开信息；1v1 中对手身份公开可直接判敌
- AI 视野：不能读其他玩家未公开身份、手牌内容、牌堆内容、未翻开的判定牌和拼点牌；用 Proxy 视图做自动化检查（tools/ai_vision_check.js）
- AI 身份推断只能基于公开行为（对主公的敌意 / 援助、对谁出伤害牌或帮助牌），推断结果存在 AI 自己的对象上

## 9. 待人工决策 / 尚未实施
- 手气卡（mulliganPhase）仍停用
- 周泰、张角、于吉无语音
- safe-area 需真机复核
- 真机手感（按钮好不好按、牌好不好选）需要用户实际游玩确认

## 10. 主菜单（第五轮定，参照 docs/主菜单与比例示意v7.png）
- 标题一行；左栏开局设置（模式 3×2、武将包含变体扩展、牌堆、高级设置收起为一行摘要），右栏操作（开始游戏主按钮带设置摘要、继续游戏带存档信息、读取存档 + 自动演示小按钮）
- 去掉英文副标题；节奏、AI 难度属于低频设置，收起
- 没有任何存档时「读取存档」显示为禁用样式，第二行写「暂无存档」
- 模式顺序：五人身份局（首次默认）、单挑、八人身份局、2v2、3v3、斗地主；牌堆顺序：标准 · 108 张（首次默认）、标准 + 军争 · 160 张；已有保存的菜单选择时按上次选择恢复

## 11. 牌桌比例（第五轮定）
- 以手牌高度 H 为基准：中央打出的牌 0.9–1.0 H（792×323 下 ≥48×66），武将牌约 0.95 H，动作按钮 40px（约 0.45 H）
- 打出的牌上方标出牌人；中央打出的牌直接复用手牌的牌面组件按比例缩放（卡图自带书法牌名，不要再叠加一套花色点数和牌名，否则会互相覆盖）
- 按钮禁用态用灰色描边，不能让不可点的按钮看起来像主按钮

## 12. 新增经验教训（第五轮）
- 扩大点击热区只能用透明伪元素，不能放大带背景 / 阴影 / backdrop-filter 的元素本身（第四轮身份牌热区把武将脸模糊了）
- 座位内角标禁止使用 backdrop-filter / filter
- 新写的显示代码必须复用卡名归一化函数，检测工具要扫描页面中的拼音卡名
- 卡图本身印有书法牌名，界面上叠加的花色点数、牌名不能压在卡图上方区域
- AI 逻辑改动后要跑纯 AI 对战统计各阵营胜率，与改动前对比，防止平衡被打偏
