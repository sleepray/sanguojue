## 2. 原因分析（任务 2，附数据与文件:行）

1. **内奸 0 胜的致命根因**：1.0.7 `revelationCounts()`（`js/ai.js:91`）只统计「存活且已 revealed」的反贼，开局恒为 0；内奸因此把主公判为敌人，且 `choosePeachResponse`（`js/ai.js:1148`）内奸救主率为 0%。改为 `publicCounts()`（模式初始人数 − 已公开阵亡）+「除主公和自己外还有存活者时必须救主」硬规则后，内奸救主率 82.4%（5p）/92.0%（8p），胜率升到 9.8%/5.5%。
2. **推断「失忆」**：旧 `scanPublicEvents()`（`js/ai.js:137`）在 `recent` 滚动后清空全部推断分数，长局停止追击；改为 WeakSet 增量处理 + 每回合衰减 + 矛盾降置信，推断准确率从 75.5%/79.8% 升到 87.7%/87.8%。
3. **残局无法识别内奸**：反贼清空后，未公开者一直 neutral，主公方没有「剩下的人里必有内奸」的公开人数推断；补人数推断 + 敌意行为 + 内奸清忠臣/最后单挑逻辑。
4. **5p 与 8p 结构相反**：5p 是 2v2（内奸不能主动压反，否则主公方直接赢），8p 是 4v3（不压反则主公被集火）；同一套内奸策略必然一端崩，按公开模式区分。
5. **主公方开局观望**：主公/忠臣对未表态者 neutral，几乎不出进攻牌，反贼先手集火；通过敌意分（攻击主公的权重更高）、主公反击、忠臣护主行为修正。
6. **反贼无隐性互认**：Proxy 审计确认反贼只按公开行为集火，没有通过 role 之外的字段互认；`ai_vision_check` 250 局 0 违规。
7. **规则层无 bug**：主公 +1 体力（`js/game.js:247`）、主公先手（`js/game.js:368`）、`checkWin`（`js/game.js:1715`）均正确；忠臣救主基线已是 100%，不是原因。未改规则、未给任何阵营加牌/加体力。

## 4. 最终策略与风格

**各阵营要点**：主公对攻击过自己的人优先反击、不轻易攻击疑似忠臣（误杀弃全牌）；忠臣主公受伤害/负面牌时提高攻击者敌意、主公濒死最高优先出桃、不确定时选择护主而非观望；反贼保持公开行为集火主公、不利用非公开信息互认；内奸以「藏身份 + 保主公（除最后两人）」为核心，8p 反贼未清空前压反、5p 暗中削忠臣、最后两人全力攻主。

**9 种风格**（AI 私有，`AI.styleFor(seed,seat,role,level,mode)`，不写玩家数据/不入存档，读档同风格）：反贼 激进/观望/潜伏；忠臣 明忠/暗忠；主公 主动/稳健；内奸 早装忠/中立。easy 偏直白，hard 偏潜伏/观望/暗忠。

- 同阵营风格胜率最大差：normal 5p 4.5pp、8p 2.9pp；easy 8.7pp（5p rebel_watch 小样本）、hard 5.2pp，全部 ≤10pp。
- 识别时机（normal）：潜伏反贼比激进晚 **1.90（5p）/5.82（8p）** 回合；暗忠比明忠晚 **1.71/4.59** 回合。5p easy/hard 的暗忠「更晚」未成立，见 §8。
- 护栏全部有 audit 用例：潜伏反贼不救主、暗忠必救、内奸除最后两人必救、潜伏不杀已确认反贼队友、反贼全灭后内奸不攻主、只剩两人时攻主、主公不误杀疑似忠臣。

## 8. 仍需人工决策

1. **平均回合未达 1.5× 目标**：5p 64.07（2.15×）、8p 67.44（1.96×）。胜率从「反贼速推」变为 35–55% 拉锯后，牌堆伤害供给约 0.3–0.5/回合，单局需 20+ 净伤害；不改规则/牌堆、不降低胜率区间就无法压到 1.5×。建议接受约 2–2.2×，或另开「节奏/牌堆」任务专项处理。
2. **easy/hard 小偏差**：5p easy 主公 58.3%（+3.3pp）、反贼 31.8%（−3.2pp）；8p easy 内奸 2.8%。CI 覆盖目标边缘，继续调会与 5p/8p 相反动态冲突，建议保留并观察。
3. **8p 误伤率 7.0%**（基线 4.5%）：来自潜伏反贼洗嫌疑/控制误判，绝对量低；若要求更干净可单独收紧。
4. **5p easy/hard 暗忠「更晚被识别」未成立**（−1.10/−0.26 回合），normal 成立；属于小样本风格分布问题。
5. **玩家占座 8p 反贼 63%**：偏高但非碾压；是否需要进一步压低需产品判断。
6. **safe-area/真机手感**仍未验证；净胜率环境为纯 AI normal，真人局可能不同。
