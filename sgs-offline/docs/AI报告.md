# AI 报告（三国杀 · 单机版）

> 版本：`AI.VERSION = ai-2026.11`（`js/ai.js`）
> 基准工具：`tools/ai_bench.js`
> 数据时间：2026-11-13 14:10（Node v23.9.0）
> 说明：规则引擎（`js/game.js` / `js/cards.js` / `js/skills.js`）仍在并行迭代；本报告数据基于当时的引擎版本，重跑命令见文末。

## 0. 结论摘要

| 项目 | 改造前（30 局基线） | 改造后（100 局） |
| --- | --- | --- |
| 8p 胜率（主忠 / 反贼 / 内奸） | 16.7% / 83.3% / 0% | **43% / 52% / 5%** |
| 8p 平均回合 | 37.7 | 54.2（中位 50） |
| 8p 崩溃 / 超时 | 0 / 0 | **0 / 0** |
| 8p 非法动作 / 空转 | 3987 / 3987 | **0 / 0** |
| 8p 每局 AI 决策 | 337.1 | 254.3 |
| 8p 单局耗时 | 7.9 ms | **4.4 ms**（约 5.7 万决策/秒） |
| 1v1 先手 / 后手 | 16.7% / 83.3% | 13% / 87% |
| 1v1 非法 / 空转 | 3357 / 3357 | **0 / 0** |
| 1v1 单局耗时 | 1.4 ms | **0.4 ms**（约 11.4 万决策/秒） |

核心结论：

1. **出牌/响应/选目标的启发式被整体重写**，并以“资源守卫 + 动作可执行性二次校验”消除了旧 AI 的空转循环（原 `仁德`、`结姻`、`青囊` 在无牌时反复选择技能，触发 `phasePlay` 100 次守卫）。
2. **8p 胜率从反贼一边倒（83.3%）修到接近均衡（43/52/5）**，崩溃、超时、非法动作、空转全部为零；1v1 先手劣势经实验确认主要来自规则不对称，AI 只能小幅补偿。
3. 单局耗时显著下降：8p 平均 4.4ms、1v1 平均 0.4ms（speed=0，纯决策开销）。
4. **没有改动任何请求/应答契约**：`chooseCards` 仍返回 `[id]`，`play` 仍返回 action 对象；只改了 `js/ai.js`，新增 `tools/ai_bench.js` 与本报告。
5. 8p 平均回合从 37.7 拉长到 54.2，是“反贼速推局变少 + 桃/无懈团队救援更积极”的副作用；如果希望节奏更快，可在 `scoreTao` / `chooseWuxie` 的收益权重上回调（见第 7 节）。

### 1.2 请求/应答契约（保持不变）

| `req.type` | AI 返回 | 说明 |
| --- | --- | --- |
| `chooseGeneral` | `{ index }` | 候选武将下标 |

| `arrange` | `{ top:[card], bottom:[card] }` | 观星 |
| `pickFrom` | `cardId` | 五谷丰登 |
| `distribute` | `[{ cardId, seat }]` | 遗计分配 |

`chooseCards` 仍可返回 id（引擎的 `ask()` 会统一转成 card 对象）。没有新增请求类型，也没有依赖调用方传参；`js/main.js` 里 `new SGS.AI(game, seat, { speed })` 的三处调用无需改动。

## 2. 基准工具 `tools/ai_bench.js`

### 2.1 用法

```bash
# 默认：100 局 8p + 100 局 1v1
node tools/ai_bench.js

# 指定局数：30 局 8p + 30 局 1v1（本次回归使用的命令）
node tools/ai_bench.js 30 30

# 难度 / JSON / 详细逐局日志
node tools/ai_bench.js 30 30 --level=easy
node tools/ai_bench.js 100 100 --level=hard
node tools/ai_bench.js 2 2 --json
node tools/ai_bench.js 10 10 --verbose

# 自定义 seed（默认 8p 从 1000 起、1v1 从 5000 起）
node tools/ai_bench.js 30 30 --seed8p=2000 --seed1v1=6000
```

退出码：`0` 表示无崩溃/超时/非法动作；`1` 表示存在上述问题；`2` 表示参数错误。

### 2.2 统计口径

| 指标 | 定义 |
| --- | --- |
| 阵营胜率 | 8p：`winner === lord/rebel/renegade`（主忠合并）；1v1：先手（1 号位/忠臣）vs 后手（2 号位/反贼） |
| 平均回合 | `game.turnCount` 的均值/中位 |
| 崩溃 | `game.start()` 抛出异常或 AI `decide` 抛异常（bench 捕获并记录栈首行） |
| 超时 | 引擎 400 回合守卫（`对局超时（平局）`）或 20s 墙钟看门狗（`--timeout` 可调） |
| 每局 AI 决策 | `decide` 调用总次数 / 局数，并按 `req.type` 分类 |
| 单局耗时 | `Date.now()` 包裹 `game.start()`；`speed=0`，无动画等待 |
| 非法动作 | 返回值不符合契约/不合法：动作不在模板中、牌与模板不一致、牌不属于自己、目标不在候选、目标数越界、借刀第二目标非法、选牌数越界、拼点/观星返回结构错误等 |
| 空转（noop） | `executeAction` 前后游戏状态**与战报条数**都无变化（例如无牌仍选技能，引擎直接 return） |
| 无效动作（ineffective） | 前后游戏状态无变化，但可能只多了一条战报（例如直谏了非装备牌） |
| 连续重复 | 同一回合连续 ≥3 次选择完全相同的无效动作 |
| 全 0 分结束 | 出牌阶段所有非 `end` 动作评分 ≤ 0 时结束（正常，仅作观测） |
| 错过正分动作 | 某动作原始评分高于当前难度阈值却直接结束（normal/hard 统计；easy 有评分抖动不统计） |
| 友方伤害目标 | 伤害类单目标牌/技能（杀、决斗、火攻、强袭）明确指向友方 |
| 疑似友伤 AOE | 使用南蛮/万箭/乱击/乱武时，场上友方数量 ≥ 敌方数量（代理指标，不等于实际造成友伤） |

### 2.3 可复现性

- 所有**决策**随机数统一用 `game.rng()`（由 `seed` 初始化的 mulberry32），不再用 `Math.random()` 做选择；
- `Math.random()` 只保留在 `delay()` 的动画抖动里，`speed=0` 时不会执行；
- bench 固定 seed，因此同一版本、同一 seed 的结果可逐局复现。

## 3. 基线问题（旧 `js/ai.js`）

用 30 局 8p + 30 局 1v1（seed 1000/5000 起）跑旧 AI，除胜率外最突出的问题是**技能空转**：

| 动作 | 8p 30 局出现次数 | 其中无效/空转 | 原因 |
| --- | --- | --- | --- |
| `skill:rende`（仁德） | 3148 | 3116 | 手牌为 0/1 时仍被评分 4 选中；`materialize` 返回空牌，`useSkillAction` 直接 `return`，`phasePlay` 循环到 100 次守卫 |
| `skill:jieyin`（结姻） | 783 | 774 | 需要 2 张手牌，手牌不足时同样空转 |
| `skill:qingnang`（青囊） | 113 | 97 | 需要 1 张手牌，手牌为 0 时空转 |
| 合计 | 6426 | **3987** | 旧 AI 的“非法动作”计数与空转数完全相等，8p 30 局共 3987 次；1v1 30 局 3357 次 |

其它已确认的 AI 问题：

1. **拼点必输**：`chooseCards` 遇到“拼点”仍按价值从低到高选牌，`驱虎/天义/制霸/烈刃` 几乎必输（拼点比点数，平局算输）。
2. **无目标仍出技能**：`借刀杀人` 找不到合法第二目标时仍返回 1 个目标；`放权/结姻/青囊` 可能选到敌人；`直谏` 可能选非装备牌。
3. **对友方用伤害牌**：单目标旧逻辑虽然以敌人优先，但 `materialize` 在友方数量不足时会用 `ranked` 兜底把友方加入目标（例如方天画戟多目标）。
4. **响应送死**：`need==='sha'` 在 `hp<=1` 时 40% 概率拒绝出杀；救队友的桃只有 75% 概率且不看自己血量。
5. **无懈链理解不全**：只在“有害且未被抵消”和“有益且未被抵消”两种状态判断，无法正确处理“反抵消”和延时锦囊判定。
6. **鬼才/鬼道 60% 随机改判**：可能把友方的乐不思蜀改成功、把敌人的判定改失败。
7. **弃牌按牌面价值从低到高弃**：`杀`（5）比 `闪`（6）先被弃，残局双方容易都留闪/桃、弃杀，出现 400 回合僵局（easy 难度 seed=1006 可复现）。
8. **AOE/桃园/五谷按固定分值**：`南蛮/万箭` 固定 6 分、`桃园` 固定 -3 起算，没有按双方存活人数、手牌数、防具和身份动态计算。

## 4. 改动摘要（`js/ai.js`）

### 4.1 出牌评分：从“固定分值”改为“逐目标期望收益”

- 杀/火杀/雷杀：按目标残血、空手（大概率无闪）、主公身份、威胁度、藤甲/仁王盾/八卦、`酒` 加伤、古锭刀、烈弓等动态加权；打不动的目标（黑杀 vs 仁王盾、普通杀 vs 藤甲）直接排除。
- 桃：不再“受伤就用”。1 血必用；掉 2 血以上才主动用；掉 1 血默认留着救命，除非手牌超过当前体力（反正要弃）。
- 酒：只有“能斩杀”或“有杀可用”时才用；能配合 `酒杀` 斩杀时评分高于普通杀，保证先酒后杀。
- 无中生有：固定高收益，优先使用。
- 装备：只有“新装备价值高于当前同栏位”才换，避免用垃圾装备顶掉好装备。
- 顺手/过河：优先拆敌方武器/防具/坐骑；友方判定区有 `乐不思蜀/兵粮寸断` 时优先帮友方拆；不会为了拆敌人判定区的坏牌而帮敌人。
- 乐不思蜀/兵粮寸断：按目标威胁度、手牌数、是否主公加权；残血目标不乐。
- AOE（南蛮/万箭/乱击）：按每个目标的身份、手牌数、防具（八卦/八阵）、藤甲/帷幕/祸首/巨象免疫逐人计算期望；友方权重远高于敌方，只有“敌方收益明显为正”才出。
- 桃园结义：按双方受伤人数与身份净收益计算；五谷丰登：只有自己手牌不占优时才用。
- 铁索连环：有火杀/雷杀/火攻等属性伤害时横置未横置的敌人，否则重铸摸牌（不再无意义地只连一个敌人）。
- 借刀杀人：只接受“持武器者不是友方、被杀者不是友方”的合法双目标组合，否则不发动。
- 火攻：按自己手牌花色覆盖率和目标藤甲/残血计算成功率，花色覆盖不足时不浪费牌。
- 丈八蛇矛：只有“没有真实杀可用 / 可额外杀”且目标可命中时才用（修复藤甲目标误判）。

### 4.2 响应逻辑

- **闪**：有闪必出；`八卦/八阵` 询问一律发动。
- **杀（决斗/南蛮/万箭/乱武/借刀）**：默认出杀，不再在 1 血时随机拒绝；优先打出价值最低的杀。
- **桃**：
  - 自己濒死必救；
  - 友方濒死：主公优先必救；普通友方在自己 ≥2 血或有多张桃时救；
  - 敌人濒死不救；
  - 内奸：反贼未清空前救主公（保持“最后单挑主公”的获胜路线）。
- **无懈可击**：
  - 有害牌：目标为友方/自己且牌“即将生效”时抵消；牌“已被抵消”时，若目标为敌人则反抵消；
  - 有益牌：目标为友方且“已被抵消”时反抵消；目标为敌人且“即将生效”时抵消；
  - 延时锦囊（乐/兵粮/闪电）同理由判定者身份决定；
  - `过河拆桥` 打空手无装备的敌人收益低时不浪费无懈。
- **鬼才/鬼道**：从 `game.logs` 最后一条“X 判定（原因）：【牌】♠5”解析判定者/原因/当前判定牌，再按“对判定者有利”的目标（乐→红桃、兵粮→梅花、闪电→非黑桃2~9、铁骑/八卦→红色、雷击/暴虐→黑桃、刚烈/屯田→非红桃、悲歌→红桃/方块）选择改判牌；已经有利则不浪费手牌，非自己判定且牌价值 ≥8 时不改。
- **神速②弃装备**：优先弃价值最低的装备。

### 4.3 目标选择：身份 > 距离 > 手牌数 > 残血/威胁

- 通用目标分：身份关系 ±30、残血、空手、主公身份、威胁度；同分时优先距离更近、手牌更少、座位更小的目标。
- 单目标伤害牌（杀、决斗、火攻、强袭）只选敌人；AOE 单独按全场关系计算。
- 技能目标：
  - `仁德/青囊/结姻/放权/直谏` 只给友方（无友方可给时不发动）；
  - `反间/离间/强袭/驱虎/天义/挑衅/放逐/雷击/巧变/急袭` 优先敌人；
  - `离间` 只选两名男性敌人，且把手牌少的放在第二目标位（决斗中第二目标先响应杀，更容易打不出）；
  - `结姻/青囊` 优先最需要回血者，主公优先；
  - `直谏` 只选“手上有对应栏位装备 + 友方该栏位为空”的组合。
- `chooseCardFrom`（顺手/过拆/反馈/寒冰剑/巧变等）：
  - 对敌人：优先拆高价值武器/防具，其次手牌；**不主动拆敌人判定区的乐/兵粮**；
  - 对友方：优先拆判定区的乐/兵粮，其次手牌；
  - 反馈/顺手获得牌时同样按装备价值优先。

### 4.4 避免无效动作

- **资源守卫**：所有技能在评分阶段先检查“手牌数/目标数/装备栏”等前置条件，不满足直接 0 分（从源头消除 `仁德`、`结姻`、`青囊`、`反间`、`离间`、`直谏`、`驱虎`、`天义`、`制霸` 的空转）。
- **动作可执行性二次校验**：`choosePlay` 对每个候选动作执行 `materialize` 后，再用 `actionFeasible()` 检查牌数、牌是否在手、目标数是否达标；不通过就跳过，避免“评分正、执行空转”。
- `激将`：同一回合只尝试一次（`_jijiangTurn`），防止无蜀势力响应时反复空转。
- `急袭`：**暂时禁用**（评分 0）。原因见第 7 节：引擎 `cardText()` 对 `suit:'none'` 的虚拟牌会崩溃，属于 `skills.js/cards.js` 的问题；引擎修复后可恢复。
- `蛊惑`：normal/hard 默认不发动（声明花色/牌名依赖后续询问，收益方差大且容易空转）；easy 保留随机性。

### 4.5 选牌/拼点/弃牌

- **拼点**：`reason` 含“拼点”时按 `rank` 从高到低选（平局算输，所以点数是第一优先级，同点选低价值牌）。
- **弃牌阶段**：引入 `discardKeepValue()`：
  - 前 2 张闪优先保留，第 3 张起快速贬值；
  - 保底保留 1 张杀（第 2 张小幅加值，3 张以上贬值）；
  - 桃最多保 2 张，第 3 张起贬值；
  - 已有更好装备时，重复装备大幅贬值；
  - 残局（存活 ≤3）降低五谷/桃园价值。
  该策略把“优先弃杀”改成“优先弃多余闪/重复装备/多余桃”，8p 平均回合从 61.2 降到 53.6，并消除了 easy 的 400 回合僵局。
- 火攻：默认弃一张同花色最低价值牌；自己 1 血且唯一可弃的是桃时放弃。
- `好施/缔盟/放权/刚烈/贯石斧/享乐/流离` 等仍按 `min` 张、价值最低原则。

### 4.6 难度分级（可选）

`aiLevel` 只影响 AI 自身参数，**默认 `normal`，不改任何调用方**。

```js
// 方式一：构造时指定（推荐）
new SGS.AI(game, seat, { speed: 0, level: 'hard' });

// 方式二：等价写法
new SGS.AI(game, seat, { speed: 0, aiLevel: 'hard' });

// 默认（不传）= normal，现有 main.js 三处调用无需改动
new SGS.AI(game, seat, { speed });
```

| 参数 | easy | normal（默认） | hard |
| --- | --- | --- | --- |
| 出牌阈值 | 1.6 | 0.8 | 0.7 |
| 评分抖动 | ±1.0 | 0 | 0 |
| 出闪概率 | 80% | 100% | 100% |
| 出杀概率 | 60% | 100% | 100% |
| 救友方桃概率 | 55% | 100% | 100% |
| 无懈概率 | 50% | 100% | 100% |
| 拼点 | 随机 | 大点 | 大点 |

`AI.LEVELS` 暴露了可用难度列表，`AI.VERSION` 为当前 AI 版本号，便于调试/回归。

> 难度效果：在**同一组 seed（4000–4199，200 局）**的 1v1 对照中，normal 镜像先手胜率 18%，`hard` 先手 vs `easy` 后手为 22%，`easy` 先手 vs `hard` 后手为 16%。方向正确，但 1v1 的先后手规则差太大（见 7.2），难度只能小幅补偿。8p 对称自对弈无法直接比较强弱，easy 表现为回合更长、决策更随机。

## 7. 剩余问题与后续建议

### 7.1 引擎侧：`急袭` 会让 `cardText` 崩溃（已在 AI 侧禁用）

- 触发链路：`skills.js` 的 `jixi` 构造虚拟【顺手牵羊】时 `suit:'none'` → `cards.js` 的 `resolveDismantle → isNullified → askWuxie` 在 `reason` 里调用 `game.cardText(card)` → `game.js` 的 `cardText` 执行 `SUITS[c.suit].cn`，`SUITS['none']` 为 `undefined` → `TypeError: Cannot read properties of undefined (reading 'cn')`。
- 复现：8p seed 1033 / 1082 / 1085（旧 AI 或任何会发动急袭的 AI）。
- 临时规避：`js/ai.js` 中 `scoreSkill` 对 `jixi` 返回 0（不发动）。
- 建议修复（属于 `js/game.js` / `js/cards.js` / `js/skills.js` 范围）：
  1. `cardText()` 对未知花色兜底，例如 `const s = SUITS[c.suit] || { cn: '?' };`；
  2. 或给急袭/借刀等虚拟牌一个合法 `suit`（如 `'spade'`/原牌花色）。
  修复后把 `scoreSkill` 的 `case 'jixi'` 恢复为 7 分即可。

### 7.2 1v1 先手胜率低是规则问题，不是 AI 能单独修的

- 规则：2 号位初始手牌 +1，且 1 号位首轮摸牌 -1；AI 两边相同。
- 同一组 seed（4000–4199，200 局）对照：normal 镜像先手 18%，hard 先手 vs easy 后手 22%，easy 先手 vs hard 后手 16%。**即便先手用 hard、后手用 easy，先手也只有 22%**，说明结构性劣势远大于难度差。
- 如果希望 1v1 更公平，建议在 `js/game.js` 侧平衡（例如 1 号位首轮摸牌改为 2、或 2 号位初始手牌优势减为 0），AI 侧不宜用“座位特判”硬凑。

### 7.3 8p 平均回合从 37.7 变长到 54.2

- 原因：反贼速推局减少（胜率从 83% 降到 52%），桃/无懈的团队救援更积极，AI 更少无意义送牌。
- 如果产品更看重节奏而非均衡：可下调 `scoreTao` 的“掉 2 血才用桃”条件、限制无懈只保护主公/自己，或降低 `scoreAoe` 阈值；这些都在 `js/ai.js` 内部，可单独调参后用 bench 看胜率/回合变化。

### 7.4 内奸胜率仍偏低（100 局 5%）

- 已从 0% 提到 5%，但标准身份局内奸本就是最难赢的角色。
- 当前用“哪边人多就压哪边”的动态关系；进一步的提升需要残局状态机（何时必须杀主公、何时必须保主公、如何保证最后一刀），本次未做。

### 7.5 `蛊惑` 未启用

- 于吉的【蛊惑】声明牌名依赖后续 `chooseOption`，且收益方差大、容易空转；normal/hard 直接不用。若后续想启用，需要在 `materialize` 里记录实际扣置的牌，并在声明询问里返回真实牌名，同时接受“被质疑”的风险。

### 7.6 其它

- AI 只读取**公开信息**（身份、体力、手牌数、装备、判定区、战报），不读其他玩家的具体手牌内容；因此对“目标是否有闪/杀”只能按手牌数估计。
- `寒冰剑/贯石斧/青龙偃月刀` 等“是否发动”询问里引擎没有把目标信息带进 `req`，AI 只能按自己手牌数保守决策；后续可在 `cards.js` 的 `askOption` 里补 `targetSeat`，AI 侧可做得更准。
- `鬼才/鬼道` 依赖 `game.logs` 的“X 判定（原因）：【牌】♠5”文本；若后续战报格式变化或日志被截断，会回退为“不改判”。
- bench 的“疑似友伤 AOE”是代理口径（友方数 ≥ 敌方数即计数），不是实际友方受伤统计；真实友伤已通过“单目标伤害牌指向友方”单独计数（当前为 0）。
