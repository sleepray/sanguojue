## 1. 覆盖方式

| 护栏 | 自动化方式 | 用例 |
|---|---|---|
| 风格可复现（同 seed+seat+role+level+mode） | 直接调用 `SGS.AI.styleFor()`；构造 Game 后 AI.ensureStyle；快照/restore 后同座位再取 | T267 |
| 不同座位可不同；难度/模式差异 | 遍历固定 seed/role，断言存在座位差异；存在难度差异 | T267 |
| 读档后同座位风格不变 | `g.snapshot()` → 新 Game `restore()` → 同座位 AI 再 `ensureStyle()` | T267 |
| 风格私有 | 检查 `game.players[seat]` 无 `style`；`JSON.stringify(g.snapshot())` 无 `"style"` 字段 | T268 |
| 反贼（含潜伏）不救主公 | 直接 `choosePeachResponse({dyingSeat: lord, options:[tao]})`，styles `rebel_hidden`/`rebel_aggressive` | T269 |
| 忠臣（含暗忠）救主公 | 同上，styles `loyal_hidden`/`loyal_open` | T269 |
| 内奸救主：除主公+自己外还有其他人 → 救；只剩两人 → 不救 | 同上，`alivePlayers.length` 从 5 降到 2 | T269 |
| 潜伏反贼不击杀已确认反贼队友 | 已 `revealed` 的反贼队友 + `targetValue(sha)` / `chooseTargets(reason=杀的目标)` | T270 |
| 反贼全灭后内奸不攻击主公、优先削忠臣 | 公开死反 revealed 清空；`relation()` + `targetValue(sha)` + `chooseTargets` | T271 |
| 只剩主公+内奸时攻击主公 | 同上，忠臣设为死亡后 | T271 |
| 主公把握不足不攻击疑似忠臣 | 反贼清空、未表态疑似忠臣；`relation()` 不为 enemy、`targetValue(sha)=-100` | T272 |

这些行为都能直接调用 AI 决策/状态方法（`styleFor`、`relation`、`targetValue`、`chooseTargets`、`choosePeachResponse`），不需要改 AI 或依赖随机模拟；因此没有用固定 seed 的场景模拟脚本。

## 5. 无法自动化/边界说明

1. **“界面数据中不出现 style”**：audit 是引擎层，无法读 DOM；已断言 `game.players` 与 `game.snapshot()` 无 style，且 AI style 只存在 AI 实例。UI 渲染代码不读取该字段，因此不需要额外 DOM 用例；若后续增加 UI 展示，可另加 qa_e2e 断言。
2. T270/T271/T272 验证的是 AI 决策函数（`targetValue`/`chooseTargets`/`relation`），不是完整跑一局；引擎最终执行仍受合法性/距离/手牌约束。若要验证完整对局结果，可用固定 seed 的 simulate 观察，但本任务不以此替代单元断言。
3. 风格分布只验证“确定性/差异存在”，不统计各风格出现频率（A 的平衡统计负责整体胜率）。
4. 内奸只验证两种存活人数分支；复杂残局（多忠臣/多反贼混合）未逐一枚举，属后续平衡统计观察范围。
