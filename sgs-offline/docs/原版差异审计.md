## 0. 结论摘要

**一句话：能完整打完一局，但“像原版”的程度只有骨架——节奏颗粒度、信息反馈、模式广度、素材利用率四项都明显不足。**

| 维度 | 结论 | 最关键的一个数 |
| --- | --- | --- |
| 节奏 | 单次“出牌”接近原版，但一半 AI 决策、所有阶段切换、响应链都是 0 延迟 | 223 次 AI 决策里 **112 次（50.2%）不走延迟**；判定+摸牌+弃牌+闭月整段 **10ms** 刷完 |
| 模式 | 原版 145 个模式入口、去重约 30 类玩法；当前只有 3 个 | 3v3/国战/斗地主/构筑 1v1/全部 PvE **缺失**；1v1 有 5 处未还原 |
| 信息呈现 | 官方牌桌有 73 个 `TableUI` 组件；当前缺倒计时、AI 思考灯、方向线、技能横幅、工具栏、MVP 结算 | 官方座位 **174×232 竖版**，当前 **172×130 横版** |
| 素材 | 范围覆盖不错，但“有文件没接上” | 69.41MB 中 **27.72MB 完全未被引用**；**116 条技能语音 + 2 条 BGM 从未播放** |

> 关键更正：`docs/原版对照自查.md` 写的“阶段切换 600–800ms 横幅”只是 **780ms 的非阻塞 CSS 动画**，引擎实际阶段等待为 **0ms**；不能据此认为节奏已对齐。

### 2.4 实测证据（Chrome CDP，2026-11-13 12:14）

一局 8 人身份局（seed=11），在 `#log-body` 上挂 MutationObserver 记录新增战报时间：

| 观测 | 数值 |
| --- | --- |
| AI 两张牌之间的间隔 | **1020 / 1027 / 1031ms**（≈ PACE 1000 + 浏览器调度） |
| 出牌 → 结算 | **120–128ms** |
| 判定 → 跳过出牌 → 摸牌 → 弃牌 → 闭月 | **合计 10ms**（相邻 dt=3/1/1/4/1/0ms） |
| 相邻战报 <250ms 的占比 | **15 / 23 = 65.2%** |
| 最小间隔 | **0ms** |
| JS 异常 | 0 |
| 404 | 仅 `favicon.ico` |

同局还观察到 3 连【无懈可击】在数秒内结束：

```
孙策 使用【过河拆桥】→ 关羽
关羽 使用【无懈可击】抵消
马超 使用【无懈可击】反抵消
关羽 使用【无懈可击】抵消
```

这 3 次响应分别来自 3 个不同 AI，全部 0ms 决策，玩家只看到战报瞬间刷 4 行。

| 模式 | 局数 | 结果 |
| --- | --- | --- |
| 8p | 3（seed 1000–1002） | 全部结束，0 失败，7–92 回合 |
| 5p | 5（seed 2000–2004） | 全部结束，0 失败，13–30 回合 |
| 1v1 | 5（seed 2000–2004） | 全部结束，0 失败，4–20 回合；其中 2 局在 speed=0 下仍耗时 >60s，性能需关注（未判定为死循环） |

### 2.5 归因结论

“AI 出牌太快”不是“AI 想得快”——当前 1000ms 甚至比原版 900ms 还慢。真正的原因是：

1. **一半决策不走延迟**（response/chooseOption/chooseCards/chooseTargets 等 112/223 次）；
2. **阶段和回合没有阻塞停顿**（原版 1500/2000/1200ms，当前 0）；
3. **单步表现只有 120–180ms**（原版 400/500ms）；
4. **判定/摸牌/弃牌一次刷完**（实测 10ms）；
5. **没有倒计时/AI 思考指示**，玩家不知道“该等多久”。

### 3.5 模式建议排序

1. **S 先做**：6 人身份、明身份场、身份演武参数（人数/难度/明暗）、非回合反馈。

3. **L 后做**：3v3/统率、国战、斗地主/主公杀、构筑 1v1/单骑无双、PvE 框架。

| 设置 | `btn_setting`/`quickSetUI`/音量/动画/自动跳过 | 无 UI（只有 `SGS_AUDIO.volume` API） | 缺 |

### 6.2 关键交互差异

1. **选将阶段没有“换将/手气卡”**：原版 1v1 明确写“1 号位可使用 1 次手气卡，2 号位 2 次”（`hd_special1v1...des`）；RuleId 75 默认 3 次。当前整套道具系统不存在，选将只是“点一张卡→确定”。
2. **没有“倒计时”这一决策压力**：官方 `countDownTimer` 748×15、`CountDownText`、`hourglassBg`、`aiTimeMax=900`；当前人类可以无限思考，AI 也没有可视的思考上限。
3. **没有“托管”**：原版预制体有 `btn_trusteeship`/`cancelTrusteeShip`；当前玩家离开只能退出。
4. **“返回”无二次确认**：`ui.js:252` 直接 `hooks.onQuit()` → `main.js:270` `session += 1; showScreen('menu')`，当前对局立即丢弃。这是最容易误触的体验问题之一。
5. **没有设置/暂停**：官方 `GameToolbar` 是 60×526 的右侧竖栏，含设置/暂停/返回等；当前只有顶栏“战报/返回”。
6. **结算没有“战绩”**：官方有 `GameZhanJiWindowNew`/`GameMvpWindowNew`/`GetZanWindow`/`ReplayOptBar`；当前只有两张玩家卡 + 胜负文案。

### 6.3 交互结论

主流程是闭环的（选将→出牌→响应→濒死→结算），但**每个决策点都缺少“时间/确认/解释”三件套**：没有倒计时、没有二次确认、没有非法原因提示。新手第一次玩会在“为什么点不动”“为什么突然结算”“为什么返回就没了”三处卡住。
