### 2.2 空城（锁定技：无手牌不能成为【杀】/【决斗】目标）

- **借刀杀人**：第二目标为空城无手牌时，杀手不能使用【杀】→ 武器交给借刀者（`cards.js` resolveCollateral）。
- **离间**：第二目标（被决斗者）为空城时拒绝发动，且不扣费用（`skills.js` case 'lijian'）。
- **乱武**：最近角色集合剔除空城；全部不可选时该角色改为失去 1 点体力（`skills.js` case 'luanwu'）。
- **流离**：转移目标候选剔除空城（`cards.js` resolveSlash）。

### 2.3 离间费用

- 去掉 `needsCards`（UI 只能从手牌点选），改为结算时用 `chooseCards` 从 **手牌+装备区** 选一张；选中装备牌走 `removeAnyCard` + `afterLoseCards`（可触发枭姬/白银狮子）。
- 先校验目标再付费：目标非法时费用不扣。AI 仍由 `selectSkillCards` 提供最便宜手牌，走原路径。

### 2.4 红颜（你的黑桃牌视为红桃牌）

- 新增 `suitOf/colorOf/effCard`（`game.js`），作为“花色视图”的唯一口径。
- **判定**：`judge()` 返回视图，不再改写牌堆实体牌（避免同一张牌离开小乔后永久变红桃）。八卦阵红判、乐不思蜀红桃不跳均生效。
- **使用**：`useVirtualCard` 的 `suit/color` 取视图 → 小乔的黑桃【杀】无视仁王盾、黑桃普通锦囊无视帷幕。
- **目标合法性**：`legalTargetsFor` 的 `color` 取视图。
- **转化**：`buildPlayActions` 的 `CONVERSIONS.test` 用视图（顺带修正“手牌中的装备牌不能转化”的旧限制，见 3.1）。
- **天香**：红桃手牌判定与弃牌池改用视图（黑桃手牌可发动）。
- **火攻**：展示牌的花色、以及使用者可弃的同花色手牌均用视图。

### 2.5 判定与改判

- `judge()` 的候选人过滤改为按“实际可用牌”判断：司马懿需有手牌，张角需有黑色手牌**或黑色装备**。
- 鬼道选项纳入装备区黑色牌，选中后 `removeAnyCard` + 弃置。

### 2.6 奸雄（获得造成伤害的实体牌）

- 原实现把虚拟牌对象放进手牌，且“两张当万箭”只处理首张，同时实体牌仍进弃牌堆（重复 id）。

## B. 存档恢复（snapshot / restore / resume）

方法：

1. `humanSeat:0` 创建对局（0 号位由 AI 代打），`onSnapshot` 收集「人类回合开始」快照；
2. 自适应挑选人类能活到第 3 个自己回合的种子（避免“人类首个回合前阵亡→永无快照”，属预期，见 D-4）；
3. 新 `Game` 上 `restore(snap)` 后逐字段比对：模式/种子/回合数/当前座位/lordSeat；每人血量/上限/存活/手牌顺序/装备槽/判定区/技能/标记/flags/used/once；牌堆与弃牌堆顺序；
4. `snapshot() → restore() → snapshot()` 往返一致；
5. 牌张总数一致，且 restore 不新增重复 id（历史重复来自 C 节已知 bug）；
6. `resume()` 续跑：回合数不回退、推进 ≥10 回合或到终局、终局 winner 合法、0 崩溃、0 未实现。

## 3. 改动

```js
case 'wuzhong': {

    break;
  }
  this.drawCards(p, 2, '无中生有');
  break;
}
```

- `targets[0] || p`：普通使用与【蛊惑】声明无中（targets 为空）两条路径都覆盖；
- `isNullified()` 内部对**全体存活角色**逐个询问（含第三方的“人类”），并支持无懈→反无懈的循环；

# 专项：死亡后仍触发“受伤后”技能（司马懿【反馈】）与死亡触发审计（2026-11-14）

## 1. 复现（修复前）

| 场景 | 修复前实际 | 应然 |
|---|---|---|
| 司马懿 hp=1 受 1 点伤害，无人救 | 仍弹出【反馈】询问；之后才阵亡 | 先濒死求桃→未救回→阵亡，**不得发动【反馈】** |

1. **结算顺序错误**：`damage()` 里 `afterDamage()` 在 `dying()`/`kill()` **之前**调用；而 `afterDamage` 的 `if (!target.alive) return` 在 hp≤0 但尚未 kill 时仍为真，于是致命伤害照样会询问“受到伤害后”技能（反馈/奸雄/刚烈/遗计/节命/放逐/新生）。
2. **失去体力不致死**：`loseHp()` 只调用 `dying()`，从未调用 `kill()`，苦肉/崩坏/乱武/强袭把角色打到 0 血后角色仍是 `alive=true`，后续技能/询问继续以“存活”身份进行。
3. **缺少死后防护**：`ask`/`drawCards`/`skillTrigger`/`颂威`/`pickCardFrom` 等入口没有统一的“死者拦截”。

## 2. 默认关闭与门控

- `GENERALS` 里 30 名变体的 `pack === 'extras'`；`PACKS` 仍只有标准/风/火/林/山五包，`extras` 不进入默认勾选。

- 引擎层 API：
  - `new SGS.Game({ packs: ['标准', …, 'extras'] })` 或 `new SGS.Game({ extras: true })`；
  - `game.setExtras(true/false)`（必须在 `start()` / `setup()` 构建选将池之前调用）；
  - `game.extrasOn()`、`game.availableGenerals()`。
- 门控点：`setup()` 的 8p/5p 将池、1v1/3v3 独立将池、斗地主地主“第二武将”池、左慈【化身】/【新生】池，统一走 `availableGenerals()`；**未开启时以上池子都完全看不到这 30 人**。
- 存档：`snapshot()` 新增 `extras` 布尔字段，`restore()` 优先按 `snap.extras`、否则按 `snap.packs` 是否含 `extras` 恢复。

## 2. “本回合非锁定技失效 / 不能使用或打出手牌”实现

义绝（黑）与铁骑都会给目标打上 `flags.noSkills` / `flags.noHand`：

- 生命周期：每次 `takeTurn` 开始时清除所有角色的 `noSkills/noHand`，即状态只持续到当前回合结束（不是目标的下个回合）。
- `noSkills` 拦截入口：
  - `skills.js` 的 `has()`：非锁定技一律视为不存在；锁定技（`SKILLS[id].locked`）不受影响。
  - 直接写在 `game.js` 的受伤后被动（奸雄/反馈/刚烈/遗计及其变体）增加 `!target.flags.noSkills` 守卫；来源侧（狂骨/趫猛/潜心/利驭/悲歌/暴虐）同样处理。
  - 判定改判（鬼才/鬼道）、天妒、颂威、天香、流离、激昂、享乐、护驾、激将、救援、枭姬、连营等入口均加守卫。
  - 转化技（武圣/龙胆/奇袭/国色…）在 `buildPlayActions` 中整体跳过。
  - 响应端：`shanOptions`/`shaOptions`/`askWuxie`/`askForPeach`/`askForNamedCard` 在 `noHand` 时不再提供手牌选项（装备技如八卦仍可正常发动）。

## 2. 新增通用异步钩子：afterCardGainHook

- `afterCardGain(p, cards)` 保持同步签名/返回值不变，结尾以 `this.afterCardGainHook(p, cards).catch(...)` 触发异步钩子，调用方无需 `await`（与既有 `afterLoseCardsHook` 同模式）。
- 钩子实现于 `skills.js`：清俭询问、选牌、选目标、加手牌上限；无技能角色时立即返回，基础对局无额外询问。
- 说明：这是 fire-and-forget 通道，极端并发场景的询问先后未确认（沿用屯田/连营的既有做法）。
